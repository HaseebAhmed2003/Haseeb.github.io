AuditMind AI

Making policy documents searchable through a backend that retrieves passages before generating an answer.

Problem and contribution

This personal project connects PDF ingestion, a FastAPI API, PostgreSQL/pgvector retrieval, and a Streamlit interface. The goal is to make a document answer inspectable alongside the filename, page, and retrieved text.

Request flow

  1. Upload a PDF. Extract text per page, with an OCR fallback for pages without text.
  2. Split each page into overlapping chunks; generate BGE-M3 embeddings and store them with page metadata in one database transaction.
  3. Embed the question; select ten candidates by cosine distance and rerank that candidate set with BM25, retaining five.
  4. Send those passages to Groq, then return the answer, source previews, latency, and retrieval similarity. Store the interaction in an audit log.

Engineering decisions

Page-level chunking keeps references traceable. A single ingestion transaction prevents partially indexed uploads. Bounded uploads and explicit error responses help the UI distinguish a completed operation from a failed dependency. The model is loaded on first use rather than during API import.

What the evidence means

The repository includes isolated regression checks and a synthetic two-page policy workflow. A local run verified synthetic PDF ingestion, real embeddings, and database retrieval. Generation is currently blocked by a rejected provider credential; it is not presented as a working live demo. The source panel shows retrieved candidates, not independently verified citations; retrieval similarity is not answer confidence.

Limitations

This is a local prototype, with no authentication, tenant isolation, or document deletion API. Documents share one retrieval corpus. Re-uploading adds duplicate chunks. There is no calibrated relevance cutoff: irrelevant passages can reach the generator. A grounding prompt asks for abstention but cannot guarantee factual answers.

OCR and model quality require separate evaluation. Professional multi-tenant backend experience is separate from this personal project.
